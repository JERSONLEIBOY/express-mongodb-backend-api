# 新服务器迁移指南

## 前置条件

- 新服务器已安装 Docker 和 Docker Compose
- 新服务器已配置 Git 和 SSH 密钥
- 已准备好数据库备份文件（如 `ele_admin_backup_YYYYMMDD_HHMMSS.tar.gz`）

## 一、克隆代码仓库

```bash
# 1. 克隆项目
sudo mkdir -p /opt
cd /opt
sudo git clone https://github.com/JERSONLEIBOY/express-mongodb-backend-api.git express-mongodb-backend-api
cd express-mongodb-backend-api

# 2. 设置 Git 安全目录（避免 dubious ownership 警告）
sudo git config --global --add safe.directory /opt/express-mongodb-backend-api
```

## 二、配置环境变量

```bash
# 1. 复制模板文件
sudo cp .env.production.template .env.production

# 2. 编辑 .env.production
sudo nano .env.production
```

**关键配置项（必须修改）：**

```bash
# 服务器公网 IP 或域名
SERVER_URL=<新服务器IP或域名>

# MongoDB 连接 URI（密码特殊字符需 URL 编码）
# 例如密码 "fuliang0829!@#" 应编码为 "fuliang0829%21%40%23"
MONGODB_URI=mongodb://admin:fuliang0829%21%40%23@mongodb:27017/ele_admin?authSource=admin

# MongoDB 用户名和密码（原始值，不需要编码）
MONGO_ROOT_USERNAME=admin
MONGO_ROOT_PASSWORD=fuliang0829!@#

# MongoDB 初始化变量（与上面保持一致）
MONGO_INITDB_ROOT_USERNAME=admin
MONGO_INITDB_ROOT_PASSWORD=fuliang0829!@#

# JWT 密钥（保持与旧服务器一致）
JWT_SECRET=cE8fK9mM2pQ5nT7wX3yZ1vB4dF6gH8jL0nM4oP6qR8sT0uV2wX4yZ6a88cD0eF2gH4iJ6

# CORS 来源（根据需要修改）
CORS_ORIGIN=*
```

**URL 编码对照表：**
- `!` → `%21`
- `@` → `%40`
- `#` → `%23`
- `$` → `%24`
- `%` → `%25`
- `&` → `%26`
- `+` → `%2B`
- `/` → `%2F`
- `:` → `%3A`

## 三、启动服务

```bash
# 1. 构建并启动所有容器
sudo docker compose up -d

# 2. 查看容器状态
docker ps | grep ele_admin

# 3. 查看应用日志（确认 MongoDB 连接成功）
docker logs --tail 50 ele_admin_backend

# 4. 查看 MongoDB 日志
docker logs --tail 50 ele_admin_mongodb
```

**预期日志输出（应用成功启动）：**
```
MongoDB connected successfully
Server is running on port 3000
Environment: production
```

## 四、恢复数据库备份

```bash
# 1. 上传备份文件到服务器
# 使用 scp 或其他方式将备份文件上传到服务器

# 2. 解压备份文件
tar -xzf ele_admin_backup_YYYYMMDD_HHMMSS.tar.gz

# 3. 复制备份到 MongoDB 容器
sudo docker cp mongo-backup ele_admin_mongodb:/tmp/

# 4. 执行恢复（使用 --drop 选项清空现有数据）
docker exec ele_admin_mongodb mongorestore \
  -u admin \
  -p 'fuliang0829!@#' \
  --authenticationDatabase admin \
  --db ele_admin \
  --drop \
  /tmp/mongo-backup/ele_admin

# 5. 验证数据恢复
docker exec ele_admin_mongodb mongosh \
  -u admin \
  -p 'fuliang0829!@#' \
  --authenticationDatabase admin \
  ele_admin \
  --eval "db.users.countDocuments()"

# 应返回用户数（如 3）

# 6. 清理临时文件
sudo rm -rf mongo-backup
docker exec ele_admin_mongodb rm -rf /tmp/mongo-backup
```

## 五、安全验证

### 5.1 验证 MongoDB 认证

```bash
# 无密码访问应被拒绝
docker exec ele_admin_mongodb mongosh ele_admin --eval "db.users.countDocuments()"
# 预期输出：MongoServerError: command aggregate requires authentication
```

### 5.2 验证端口隔离

```bash
# 检查 27017 端口未暴露到公网
sudo netstat -tlnp | grep 27017
# 预期输出：无结果（端口未监听公网）

# 检查容器端口配置
docker ps | grep ele_admin_mongodb
# 预期输出：只显示 "27017/tcp"，没有 "0.0.0.0:27017"
```

### 5.3 配置防火墙（额外防护层）

```bash
# 添加 iptables 规则，只允许本地访问 27017
sudo iptables -I INPUT 1 -s 127.0.0.1 -p tcp --dport 27017 -j ACCEPT
sudo iptables -I INPUT 2 -s ! 127.0.0.1 -p tcp --dport 27017 -j DROP

# 保存规则（CentOS/RHEL）
sudo service iptables save

# 或者（Ubuntu/Debian）
sudo iptables-save | sudo tee /etc/iptables/rules.v4

# 验证规则
sudo iptables -L INPUT -n --line-numbers | grep 27017
```

### 5.4 测试应用接口

```bash
# 测试根路由
curl http://localhost:3000/

# 预期输出：
# {"name":"Express MongoDB Backend API","version":"1.0.0","documentation":"/api-docs"}

# 测试 API 文档
curl http://localhost:3000/api-docs/

# 测试不存在的路由（验证错误处理）
curl http://localhost:3000/api/test
# 预期输出：{"code":404,"message":"路由 /api/test 不存在","data":null}
```

## 六、配置 GitHub Actions Secrets

在 GitHub 仓库设置中更新以下 Secrets（如果新服务器 IP/域名变化）：

1. 进入 GitHub 仓库 → Settings → Secrets and variables → Actions
2. 更新 `SERVER_URL` Secret：
   - Name: `SERVER_URL`
   - Value: `<新服务器IP或域名>`

## 八、常见问题排查

### 问题 1：应用报错 "URI contained empty userinfo section"

**原因**：`MONGODB_URI` 中的用户名或密码为空

**解决方案**：
1. 检查 `.env.production` 文件中的 `MONGODB_URI` 是否完整
2. 删除并重新创建容器：
   ```bash
   sudo docker compose down
   sudo docker compose up -d
   ```

### 问题 2：应用报错 "Unable to parse :27017 with URL"

**原因**：密码包含特殊字符但未进行 URL 编码

**解决方案**：
1. 修改 `.env.production` 中的 `MONGODB_URI`，将密码特殊字符进行 URL 编码
2. 重新创建容器：
   ```bash
   sudo docker compose rm -sf app
   sudo docker compose up -d app
   ```

### 问题 3：MongoDB 认证失败

**原因**：`MONGO_INITDB_ROOT_USERNAME` 和 `MONGO_INITDB_ROOT_PASSWORD` 未正确设置

**解决方案**：
1. 检查 `.env.production` 文件中这两个变量是否存在
2. 如果 MongoDB 容器已初始化过，需要删除数据卷重新初始化：
   ```bash
   sudo docker compose down -v
   sudo docker compose up -d
   ```
   **警告**：此操作会删除所有 MongoDB 数据！先备份数据。

### 问题 4：防火墙规则重启后丢失

**解决方案（CentOS/RHEL）**：
```bash
sudo service iptables save
sudo systemctl enable iptables
```

**解决方案（Ubuntu/Debian）**：
```bash
sudo apt-get install iptables-persistent
sudo netfilter-persistent save
```

## 九、监控和维护

### 日志查看

```bash
# 应用日志
docker logs -f ele_admin_backend

# MongoDB 日志
docker logs -f ele_admin_mongodb

# 只查看错误日志
docker logs ele_admin_backend 2>&1 | grep -i error
```

### 备份数据库

```bash
# 创建备份目录
mkdir -p ~/backups
cd ~/backups

# 执行备份
docker exec ele_admin_mongodb mongodump \
  -u admin \
  -p 'fuliang0829!@#' \
  --authenticationDatabase admin \
  --db ele_admin \
  --out /tmp/mongo-backup

# 复制备份到宿主机
docker cp ele_admin_mongodb:/tmp/mongo-backup ./mongo-backup

# 压缩备份
tar -czf ele_admin_backup_$(date +%Y%m%d_%H%M%S).tar.gz mongo-backup

# 清理临时文件
sudo rm -rf mongo-backup
docker exec ele_admin_mongodb rm -rf /tmp/mongo-backup
```

### 定期备份（Cron 任务）

```bash
# 创建备份脚本
sudo nano /opt/backup_mongodb.sh
```

**脚本内容**：
```bash
#!/bin/bash
BACKUP_DIR="/opt/backups"
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_NAME="ele_admin_backup_${DATE}"

mkdir -p ${BACKUP_DIR}
cd ${BACKUP_DIR}

# 执行备份
docker exec ele_admin_mongodb mongodump \
  -u admin \
  -p 'fuliang0829!@#' \
  --authenticationDatabase admin \
  --db ele_admin \
  --out /tmp/mongo-backup

# 复制备份
docker cp ele_admin_mongodb:/tmp/mongo-backup ./mongo-backup

# 压缩备份
tar -czf ${BACKUP_NAME}.tar.gz mongo-backup

# 清理临时文件
rm -rf mongo-backup
docker exec ele_admin_mongodb rm -rf /tmp/mongo-backup

# 只保留最近7天的备份
find ${BACKUP_DIR} -name "ele_admin_backup_*.tar.gz" -mtime +7 -delete

echo "Backup completed: ${BACKUP_NAME}.tar.gz"
```

**设置权限并添加到 Cron**：
```bash
sudo chmod +x /opt/backup_mongodb.sh

# 每天凌晨2点执行备份
sudo crontab -e
# 添加以下行：
0 2 * * * /opt/backup_mongodb.sh >> /var/log/mongodb_backup.log 2>&1
```

## 十、旧服务器下线

在确认新服务器运行稳定后（建议观察 3-7 天）：

1. **验证数据完整性**
   ```bash
   # 对比新旧服务器的文档数量
   docker exec ele_admin_mongodb mongosh \
     -u admin \
     -p 'fuliang0829!@#' \
     --authenticationDatabase admin \
     ele_admin \
     --eval "db.getCollectionNames().forEach(c => print(c + ': ' + db[c].countDocuments()))"
   ```

2. **更新客户端配置**
   - 将所有客户端应用的 API 地址指向新服务器

3. **停止旧服务器服务**
   ```bash
   sudo docker compose down
   ```

4. **最终备份**
   - 在旧服务器上执行最后一次完整备份
   - 下载备份文件到本地保存

5. **释放资源**
   - 确认一切正常后，可以释放旧服务器
